# myTravel — доступность (WCAG 2.2)

Раздел брендбука для дизайнеров, верстальщиков и QA. Источник цвета —
`tokens/tokens.css`. Контекст продукта: авиабилеты, отели, круизы, туры,
аренда авто и квартир, трансфер, виза, страховка, экскурсии, автобус/ЖД,
карго, концерты. Люди платят с телефона, часто в спешке, на дешёвых
Android и медленном интернете, на трёх языках — русский, узбекский
(латиница), английский. Бренд-цвет `--mt-anor-600` — гранатовый — это и
цвет главного действия, поэтому **ошибка никогда не обозначается одним
красным** (§3).

Числа контраста ниже посчитаны скриптом `contrast.py` (формула WCAG 2.1:
относительная яркость sRGB → gamma 2.4 → `(L_light + 0.05) / (L_dark +
0.05)`), а не подобраны на глаз. Прогон по всем значениям `tokens/tokens.css`
— светлая тема и `[data-theme="dark"]`.

## 1. Целевой уровень и критерии WCAG 2.2

**База — WCAG 2.2 AA для всего продукта. AAA — обязательно** для
основного текста (`--mt-text` / `--mt-n-900`), всего, что связано с
деньгами (цена, штраф, сумма возврата), и статусов оплаты/бронирования
(await/ok/cancel/refund). Где токен не дотягивает до AAA в денежном
контексте — явно показано в §2, «Что не проходит», без сглаживания.

Критерии 2.2, добавленные к 2.1 и релевантные продукту:

| Критерий | Что требует | Где |
|---|---|---|
| **2.4.11 Focus Not Obscured** | Элемент в фокусе не скрыт залипающей шапкой, нижней панелью навигации или плашкой оплаты | §5 |
| **2.5.7 Dragging Movements** | У любого drag-действия (слайдер дат, свайп карточки) есть альтернатива без перетаскивания | §4, §6 |
| **2.5.8 Target Size (Minimum)** | Цель ≥ 24×24px либо ≥24px до соседней цели. Стандарт продукта — `--mt-tap-min: 44px`, жёстче минимума | §4 |
| **3.3.7 Redundant Entry** | Нельзя второй раз в одном процессе спрашивать уже введённые данные (паспорт при визе → паспорт при страховке в том же заказе) | §6 |
| **3.3.8 Accessible Authentication** | Вход/подтверждение (OTP, 3-D Secure) не требует когнитивного теста (капчи) без альтернативы | §6, §8 |

### Что в палитре не проходит и как с этим жить

1. **`--mt-urik-500` как текст — FAIL в светлой теме (2.01–2.16:1).**
   Замена: только `--mt-urik-700` (5.31:1). `--mt-urik-500` остаётся
   точкой статуса, плашкой ≤10% площади, заливкой бейджа под текстом
   другого цвета.

2. **`--mt-border`/`--mt-border-strong` не проходят 3:1 нигде
   (1.24–1.73:1), в обеих темах.** Граница — декоративный раздел, не
   единственный носитель состояния. Для состояний, которые обязаны
   быть различимы (invalid-инпут, выбранный чекбокс, активная карточка
   тарифа): толстая обводка акцентным цветом (`--mt-anor-700` для
   ошибки — 2px, 9.94:1 к error-bg), плюс иконка/чек, плюс заливка
   `--mt-surface-alt`. Обычная `--mt-border` — только «мягкое»
   визуальное разделение, где потеря границы не меняет смысла экрана.

3. **`--mt-anor-600` текстом на каймаке — AA (6.76:1), не AAA,** хотя
   цена — денежный контекст с целевым AAA. На чистом `--mt-surface`
   (white) та же пара — 7.27:1 (AAA), потому что n-50 темнее white.
   Замена: акцентный текст (выделенная скидка, ссылка «Изменить
   тариф») прямо на каймачном фоне — `--mt-anor-700` (8.73:1, AAA);
   `--mt-anor-600` — только фон кнопки, где поверх всегда белый текст
   (уже 7.27:1, AAA).

4. **Статус await/warning в светлой теме — 4.99:1, AA, не AAA.**
   Единственный из четырёх статусов ниже AAA-цели для платёжных
   статусов. `--mt-urik-700` уже близок к максимально тёмному варианту
   курагового тона, дальше он читается как «коричневый», а не «урюк».
   Два варианта: (а) принять AA как осознанное исключение — await это
   ожидание, а не потеря денег, критичность ниже, чем у
   error/cancel/refund; (б) для строгой AAA-политики без исключений —
   завести `--mt-urik-800` только для текста await в критичных местах
   (шапка заказа, письмо). Решение по умолчанию — вариант (а),
   зафиксирован как осознанный компромисс, а не пропуск.

5. **`--mt-accent-fg` на `--mt-accent` в тёмной теме — 4.59:1, запас
   0.09 от AA.** Не применять к этой паре прозрачность,
   `filter: brightness()` или полупрозрачные оверлеи pressed/disabled
   без повторной проверки — любое смещение luminance на 1–2 пункта
   роняет пару ниже 4.5:1.

6. **`--mt-n-500` как обычный текст — FAIL для тела текста
   (3.47–4.04:1).** Подтверждено расчётом: комментарий в токенах
   («только крупный текст») верен. Использовать только для текста
   ≥24px обычного начертания / ≥18.66px bold. Для подписей и
   второстепенного текста любого размера — `--mt-n-600` (AA везде).

## 3. Цвет никогда не единственный носитель смысла

`--mt-anor-600` — это и цвет ошибки эквайринга, и цвет кнопки
«Оплатить». Если статус выражен только оттенком красного, интерфейс на
секунду читается как «нажми сюда, чтобы заплатить». У каждого статуса —
три независимых канала: **иконка + точка + текст**, они не дублируют
смысл, а усиливают его.

| Статус | Иконка | Точка (`*-dot`) | Текст | Фон |
|---|---|---|---|---|
| Ожидает оплаты | часы | `--mt-status-await-dot` (urik-500) | «Ждём оплату» | `--mt-status-await-bg` |
| Подтверждено | галочка в круге | `--mt-status-ok-dot` (success) | «Подтверждено» | `--mt-status-ok-bg` |
| Отменено | минус в круге | `--mt-status-cancel-dot` (n-500) | «Отменено» | `--mt-status-cancel-bg` |
| Возврат | стрелка назад | `--mt-status-refund-dot` (indigo-500) | «Возврат» | `--mt-status-refund-bg` |

**Почему «отменено» нейтральное (n-700/n-200/n-500), а не красное.**
Красный занят: это гранат кнопки действия. Если «Отменено» тоже
красное, взгляд, скользящий по списку заказов в спешке, на долю
секунды путает статус с призывом к действию. Нейтральный серый читается
как «этот пункт неактивен» — заказ вышел из жизненного цикла и не
требует решения прямо сейчас. Красным остаётся только реальная угроза
денег: ошибка платежа, истекающий таймер.

**Проверка «через монохромный фильтр».** Перед сдачей макета — скриншот
списка заказов через `filter: grayscale(1)` или эмуляцию
`forced-colors` (§12). Если статусы неразличимы без цвета — не готово.

**Ссылки.** `--mt-link` всегда с `text-decoration: underline`, а не
только цветом — иначе человек с дальтонизмом (протанопия/дейтеранопия,
~8% мужчин) не отличит ссылку от текста абзаца.

## 4. Тап-зоны

Стандарт — `--mt-tap-min: 44px`, жёстче минимума 2.5.8 (24×24px).
Расстояние между соседними целями — не меньше `--mt-space-2` (8px) по
свободному краю, если сами цели меньше 44px.

**Плотные строки результатов поиска.** Карточка рейса/отеля не
дробится на мелкие кликабельные зоны (цена/время/кнопка отдельно) —
весь блок результата является одной тап-целью высотой ≥44px на всю
ширину карточки. Вторичные действия внутри («Подробнее о тарифе»,
«Добавить багаж») получают собственные 44×44px зоны с
`--mt-space-2`-отступом от края карточки.

**Календарь.** Сетка 7×n на 360px не даёт 44px по высоте (обычно
32–36px строка). Решение: видимый размер ячейки может быть меньше
44px, но **тап-зона** — невидимый `padding` внутри `<button>` (не
`margin`), расширяющий кликабельную область до 44×44px за счёт
соседних зазоров сетки. Если и после этого центры ячеек ближе 8px друг
к другу — заменить сетку на список дат там, где нужна ровно одна дата
(«выезд»), сетку-календарь оставить для диапазона (тур, аренда).
Текущий/выбранный день/день с низкой ценой различаются не только
заливкой, но и текстом/иконкой — та же логика §3.

**Большие пальцы, экран 6.7".** Верхние углы недостижимы большим
пальцем при одноручном хвате. Первичное действие («Оплатить»,
«Выбрать») — нижняя треть экрана, на всю ширину минус поля, ≥44px
(на практике 52–56px). Второстепенные действия (назад, поделиться) —
верх, они не требуют быстрой реакции. Drag нигде не единственный способ
(2.5.7): слайдер цены в фильтрах и диапазон дат дублируются полями
ввода с клавиатурой/степпером.

## 5. Фокус

```css
:where(a, button, input, select, textarea, summary, [tabindex]):focus-visible {
  outline: var(--mt-focus-width) solid var(--mt-focus); /* 2px */
  outline-offset: var(--mt-focus-offset); /* 2px */
  border-radius: var(--mt-radius-sm);
}
```

Контраст `--mt-focus` к любой поверхности продукта — 6.06:1 и выше в
обеих темах (§2.6), обводка всегда читается.

**`:focus-visible`, не `:focus`.** Обводка появляется при клавиатуре/
переключателе и не появляется при тапе или клике мышью — иначе кольцо
на каждой кнопке при тапе выглядит багом. Без поддержки
`:focus-visible` — безопасная деградация до обычного `:focus`.

**Порядок обхода.** DOM = визуальный порядок = порядок чтения (цена →
время → багаж → «Выбрать» — и в разметке, и в табличном виде для
десктопа). `tabindex` больше 0 не используется никогда.

**Скип-линк.** Первый фокусируемый элемент — «Перейти к результатам» /
«Перейти к содержимому», видимый только в фокусе, ведёт к `<main>`.
Обязателен на странице выдачи с длинным блоком фильтров.

**Ловушка фокуса в модалках и шитах.** Открытие переносит фокус на
первый интерактивный элемент (или заголовок) и запирает `Tab`/
`Shift+Tab` внутри, пока модалка открыта. `Esc` и кнопка «Закрыть»
возвращают фокус на элемент, который её открыл. Фон получает
`aria-hidden="true"`/`inert`.

**2.4.11 Focus Not Obscured.** У нас минимум два залипающих слоя:
шапка с поиском/фильтрами и нижняя панель цены на шаге бронирования.
Ни один не должен полностью закрывать элемент в фокусе:
- скроллящийся список со залипающей нижней панелью — `scroll-padding-bottom`
  равный высоте панели + `--mt-space-4`, чтобы `scrollIntoView()` и
  табуляция не прятали поле под панель;
- залипающая шапка — аналогичный `scroll-margin-top` на секциях;
- модалка выше экрана — внутренний скролл (`overflow-y: auto`), а не
  растяжение страницы, иначе фокус «уезжает» за шапку модалки.

## 6. Формы и деньги

**Label всегда видимый.** Ни одно поле оплаты/пассажира/адреса не
полагается на `placeholder` как единственную подпись — он исчезает при
вводе, и человек, отвлёкшийся посреди заполнения паспортных данных,
теряет контекст. Подпись — постоянный `<label for>`, кегль не меньше
`--mt-text-14`, цвет не бледнее `--mt-n-600`.

| Поле | `type`/`inputmode` | `autocomplete` |
|---|---|---|
| Телефон | `type="tel"` `inputmode="tel"` | `tel` |
| Номер карты | `inputmode="numeric"` | `cc-number` |
| Срок действия карты | `inputmode="numeric"` | `cc-exp` |
| CVV | `inputmode="numeric"` | `cc-csc` |
| Email | `type="email"` `inputmode="email"` | `email` |
| Номер паспорта | `inputmode="text"` | `off`, но подставляется из профиля (см. ниже) |
| OTP из SMS | `inputmode="numeric"` | `one-time-code` |

**Ошибки — рядом с полем.** Текст ошибки под полем, связан через
`aria-describedby`, поле — `aria-invalid="true"` на время ошибки:

```html
<label for="card-number">Номер карты</label>
<input id="card-number" inputmode="numeric" autocomplete="cc-number"
       aria-invalid="true" aria-describedby="card-number-err">
<p id="card-number-err">Карта не прошла проверку. Проверьте срок действия и CVV.</p>
```

Текст ошибки — по словарю `docs/voice-and-tone.md`: причина, потом код,
без обвинения пользователя. Сводный статус над кнопкой «Оплатить»
(«Проверяем платёж…» → «Банк отклонил платёж») —
`aria-live="polite" aria-atomic="true"`, чтобы прочитать изменение
целиком один раз, не дублируя `aria-describedby` полей.

**Соединение обрывается — данные не теряются.** Поиск и выбранные
места сохраняются локально до восстановления сети (пример текста —
`docs/voice-and-tone.md` §6.6); форма оплаты не сбрасывает введённые
поля (кроме CVV, который не хранится).

**3.3.7 Redundant Entry.** Паспорт, введённый на шаге визы, подставляется
автоматически на шаге страховки того же заказа с пометкой «как в
визовой заявке, можно изменить», а не пустым полем. Телефон/email/
сохранённая карта из профиля подставляются во все формы заказа с
возможностью правки.

**3.3.8 Accessible Authentication.** OTP-поле —
`autocomplete="one-time-code"`, чтобы iOS/Android подставляли код без
переключения в «Сообщения». Капча (текстовая/графическая) не ставится
как обязательный шаг перед входом или оплатой — это запрещённый
когнитивный тест без альтернативы. Антифроду — поведенческий анализ или
one-tap push, не «введите цифры с картинки».

## 7. Три языка и типографика

**Минимальный кегль основного текста — 16px** (`--mt-text-16` = `1rem`).
Поля `<input>` мельче 16px заставляют iOS Safari зумить экран при
фокусе — на форме оплаты это ломает раскладку. Все `<input>`,
`<select>`, `<textarea>` — не меньше 16px, даже если 14px компактнее
впишется в мобильную форму.

**Узбекский текст длиннее русского на 10–20%** (агглютинация,
`docs/voice-and-tone.md` §9.1): `[ Ijarani bekor qilish va 840 000
soʻm olish ]` не влезает в ширину, рассчитанную под «Отменить аренду».
Кнопки и бейджи — `width: auto` с `min-width`, не жёсткий `width`;
если текст не влезает — сокращаем его под язык, не уменьшаем кегль
ниже `--mt-text-14`.

**`lang` на `<html>` и на вставках.** Корневой `lang` переключается с
языком интерфейса. Смешанные фрагменты (`Turkish Airlines` в русском
тексте, паспортное имя латиницей) — в `<span lang="en">`, чтобы
VoiceOver/TalkBack произносили их на нужном языке, а не по
русско-фонетическим правилам.

**`oʻ`/`gʻ` — U+02BB, не апостроф.** Правило и типичные ошибки — в
`docs/voice-and-tone.md` §5. Для доступности это не только орфография:
диктор на ASCII `'` внутри `to'lov` иногда читает «штрих» или обрывает
слово, а корректный U+02BB в шрифтах `fonts/` читается без паузы.
Перед сдачей — тот же поиск по `'`/`’`/`` ` `` в uz-строках.

**Без переноса в номерах рейсов и суммах.** `TK 371`, `MT-4471982`,
`4 850 000 сум` — `white-space: nowrap` или неразрывный пробел U+00A0
между разрядами, плюс `.mt-num` из `tokens.css` (`tabular-nums`), чтобы
колонка цен не «дышала» и не переносилась на 360px.

## 8. Движение и анимация

`tokens.css` уже обнуляет `--mt-duration-*` и ставит
`animation-duration: 0.01ms !important` при `prefers-reduced-motion:
reduce` — этого достаточно для CSS; для ручных JS-анимаций (canvas,
`requestAnimationFrame`) флаг нужно продублировать в коде.

**Карусели не автопрокручиваются.** Только действие пользователя
(свайп, стрелка, точки), без автотаймера; если ротация всё же нужна —
пауза на наведении/фокусе и без автозапуска заново.

**Ограничение мигания.** Ничего не мигает быстрее 3 раз/сек (2.3.1);
пульсация точки статуса — плавная, и с `prefers-reduced-motion`
становится статичной.

**Таймер «держим место 19:42».** Одного визуального таймера
недостаточно: не читается скринридером построчно и является
единственным носителем дедлайна. Решение:
- текст рядом на человеческом языке — «Место держим до 19:42», не
  только цифры отсчёта;
- `aria-live="polite"` обновляется не каждую секунду (заглушит
  скринридер), а при смене минуты, плюс отдельное более заметное
  сообщение за 2 минуты до истечения;
- **2.2.1 Timing Adjustable** — способ продлить лимит до истечения
  («Ещё немного времени»), если поставщик это позволяет; если
  продление невозможно — заранее объяснить, что произойдёт и что
  делать («если время выйдет, начните поиск заново — оплата не
  спишется»), без тихого сброса.

## 9. Скринридеры и ассистивные технологии

**Иконки-кнопки.** Конвенция для SVG в `icons/`: самостоятельная
кнопка-иконка несёт `<title>` внутри `<svg>` с уникальным `id`, кнопка
ссылается на него через `aria-labelledby`:

```html
<button type="button" aria-labelledby="icon-share-label">
  <svg role="img" aria-labelledby="icon-share-label">
    <title id="icon-share-label">Поделиться ваучером</title>
    <use href="/icons/share.svg#icon"></use>
  </svg>
</button>
```

Иконка рядом с видимым текстом того же смысла — `aria-hidden="true"`,
подпись не дублируется.

**`aria-live` для статуса оплаты.** Переход «Проверяем платёж…» →
«Оплата прошла»/«Банк отклонил платёж» озвучивается через
`aria-live="polite"` (§6) без необходимости обходить экран вручную.

**Таблицы результатов поиска.** Данные с чёткими колонками (цена,
время, багаж) — семантическая `<table>` с `<th scope="col">`, либо
`role="list"`/`role="listitem"` с `aria-label`, объясняющим значение
вне визуальной колонки: «Цена: 4 850 000 сум», а не голое число.

**Порядок чтения ваучера.** DOM-порядок: номер заказа → маршрут/услуга
→ дата и время → пассажир(ы) → место/номер брони у поставщика → что
взять с собой → контакты поддержки. Заголовок первого уровня — маршрут
или название услуги, не логотип и не слово «Ваучер».

**Печатная версия.** Статус, переданный на экране цветным бейджем, в
печати дублируется текстом («Подтверждено» рядом со значком) — лист
без цвета не должен превращать разные статусы в одинаковый серый
прямоугольник.

## 10. Медленный интернет и дешёвые устройства как часть доступности

Пользователь с когнитивной или моторной особенностью на медленном
интернете страдает от плохой производительности сильнее среднего:
дольше держит внимание на экране, чаще теряет прогресс при подвисании.

**Скелетоны вместо спиннеров.** Загрузка выдачи/деталей/статуса
показывает скелетон в форме финального контента, а не бесконечный
спиннер — даёт ориентир по объёму заранее и меньше грузит CPU/батарею
дешёвого устройства. Сопровождается текстовым статусом в
`aria-live="polite"` («Загружаем варианты»), не только визуальным
скелетоном.

**Обрыв сети.** Формула из `docs/voice-and-tone.md` §6.6: баннер, что
сохранено и что не тронуто (деньги/поиск), кнопка «Повторить»,
экономный режим (результаты без картинок). Форма оплаты не обнуляет
введённые данные карты (кроме CVV).

**Размер шрифтового пакета.** Шрифты нарезаны по скриптам
(`fonts/*-cyrillic.woff2`, `*-latin.woff2`, `*-cyrillic-ext.woff2`) и
подключаются по языку интерфейса, не одним файлом со всеми алфавитами
— меньше вес страницы, быстрее First Contentful Paint на медленном
соединении.

**Без больших градиентов и теней.** `--mt-shadow-1..3` — лёгкие,
однослойные, тёплого оттенка, не многослойные color-градиенты:
дешевле по перерисовке на слабом GPU и меньше визуального шума для
людей с когнитивными особенностями и быстрой утомляемостью зрения.

## 11. Чек-лист приёмки

**Дизайн**

- [ ] Каждый статус бронирования передан иконкой + точкой + текстом, не только цветом
- [ ] Ни один текст на цветном фоне не ниже AA (4.5:1); денежные/статусные пары — не ниже AA, исключения из §2 явно приняты
- [ ] Тап-цели ≥44×44px или имеют невидимый padding до 44px (календарь, плотные списки)
- [ ] Между соседними целями ≥8px, если сами цели меньше 44px
- [ ] Основной текст ≥16px, поля форм ≥16px
- [ ] Ни одно действие не требует drag без альтернативы (2.5.7)
- [ ] Таймеры удержания места — с текстом и способом продления или явным объяснением истечения

**Вёрстка**

- [ ] Все `<label>` видимы, ни один placeholder не используется как единственная подпись
- [ ] `inputmode`/`autocomplete` расставлены по таблице §6
- [ ] Ошибки формы — `aria-describedby` + `aria-invalid`, сводный статус — `aria-live="polite"`
- [ ] Иконки-кнопки — `<title>` + `aria-labelledby`, декоративные — `aria-hidden="true"`
- [ ] Фокус виден (`:focus-visible`, 2px `--mt-focus`, отступ 2px), ловушка фокуса в модалках/шитах реализована
- [ ] Залипающие шапка/нижняя панель оплаты не перекрывают элемент в фокусе (`scroll-padding`/`scroll-margin`)
- [ ] Скип-линк к `<main>` есть на страницах с длинными фильтрами
- [ ] `prefers-reduced-motion` учтён в ручных JS-анимациях, не только в CSS

**Тексты**

- [ ] `lang` на `<html>` соответствует языку интерфейса, вставки — в `<span lang="...">`
- [ ] `ʻ`/`gʻ` — U+02BB, апострофы U+0027/U+2019/U+02BC/`` ` `` отсутствуют в uz-строках
- [ ] Кнопки/бейджи фиксированной ширины проверены на узбекском — без переноса в 3 строки и обрезки
- [ ] Номера рейсов, коды заказов, суммы — `nowrap`/`.mt-num`
- [ ] Текст ошибки — причина, что уже сделано системой, одно действие

**Проверка вручную**

- [ ] Сценарий покупки пройден только клавиатурой (Tab/Shift+Tab/Enter/Esc), без потери фокуса
- [ ] Оплата и ваучер прочитаны VoiceOver (iOS) и TalkBack (Android), порядок чтения логичен
- [ ] Зум 200% — контент рефлоуится, ничего не обрезается по горизонтали
- [ ] Ширина 360px — кнопки и бейджи не ломаются на трёх языках
- [ ] Ваучер распечатан в чёрно-белом режиме — статус читается без цвета
- [ ] Список заказов прогнан через `forced-colors`/`grayscale` — статусы различимы без цвета

## 12. Как проверять

| Инструмент | Что смотреть |
|---|---|
| **axe DevTools** | Прогон на ключевых экранах (поиск, карточка, оплата, ваучер): контраст, отсутствующие label, неверные ARIA-атрибуты, дублирующиеся id |
| **Lighthouse (Accessibility)** | Score как регресс-метрика в CI; смотреть конкретные провалы, не только итоговое число |
| **VoiceOver Rotor (macOS/iOS)** | Ctrl+Option+U — навигация по заголовкам (иерархия h1→h2), по ссылкам (текст понятен вне контекста), по формам; отдельно ваучер и экран ошибки оплаты |
| **TalkBack (Android)** | Реальное дешёвое устройство, не только эмулятор — порядок чтения карточки результата и статус-бейджей, скорость озвучки `aria-live` при смене статуса оплаты |
| **Эмуляция `forced-colors`** (Chrome DevTools → Rendering → `forced-colors: active`) | Статусы, кнопки и границы полей остаются различимы под системными цветами High Contrast |
| **Зум 200%** | Рефлоу без горизонтального скролла, кнопки не обрезаются, залипающие панели не перекрывают контент (2.4.11) |

| **Ручная клавиатурная навигация** | Полный путь покупки без мыши: видимость фокуса на каждом шаге, отсутствие ловушек вне модалок, работа Esc в шитах |
